# Skill-description climb

## Objective

Raise how often haiku loads `structure-roblox-projects` and `roblox-resource-acquisition` for prompts that should load them, without loading them for prompts that should not. Score = mean of the two skills' positive pass rates on the search set (balanced, so one skill cannot carry the other). Direction: max. Ceiling 1.0.

Measured on 2026-10-23 before this run: `structure-roblox-projects` 6/13, `roblox-resource-acquisition` 5/13, negatives 9/9, consistent with the 2026-10-17 eval's haiku rows. The lever is each skill's `description` field in its `SKILL.md` frontmatter: that text is all the model sees before deciding to load a skill.

## Evaluator

`python -I evals/gate/climb/eval.py --cases evals/gate/climb/search.json --reps 2`: every search case through `run()` of `evals/agent-optimization-2026-10-17/harness.py` on haiku, cond `new`, this checkout as the plugin (the harness copies `skills/*` into the scaffold's `.claude/skills`, so the working tree's SKILL.md is what runs). Verdict: a positive case passes when the expected skill was loaded (Skill tool or a read of its SKILL.md); a negative case passes when no watched skill loaded; boundary cases use the route rule (loading both counts as a pass for a positive). Metrics: `srp_rate`, `rra_rate`, `neg_rate`, counts, `wrong_skill`, `cost_usd`, `mean_turns`, `errors`. Any errored run makes the score invalid.

Holdout: the same command on `holdout.json` (5 + 5 + 4 cases), gated: a new best must also beat the frontier there or it is overfit. No confirm set: there are only 35 cases in all. Splits were drawn stratified by expected skill with seed 20261023 (`split.py`), never by score.

Noise: 16 positives × 2 reps = 32 runs per score; a one-case flip moves a skill's rate by 0.0625 and the score by 0.03. Expect epsilon near 0.1 after the baseline.

## Guards

`neg_rate>=baseline` (negatives must not start loading), `srp_rate>=baseline-0.1` and `rra_rate>=baseline-0.1` (no skill may be sacrificed for the other), `errors==0`.

## Scope and cheating

Scope: `skills/structure-roblox-projects/SKILL.md` and `skills/roblox-resource-acquisition/SKILL.md`, and in practice only their `description` frontmatter. Protected: `evals/`, `.github/`, `hooks/`, `agents/`, `.claude-plugin/`.

Cheating: pasting search or holdout prompts, or near-copies of them, into a description; naming the eval's scaffolds or case ids; weakening the negatives by making a description claim everything; editing the harness or cases. Never read `holdout.json` while proposing a change. Descriptions must stay true to what the skill does: a description that over-claims raises `neg_rate` failures and misleads users in real sessions.

## Map

- `skills/<name>/SKILL.md`: frontmatter `name`, `description` (one long quoted string), then the body. Claude Code shows only `description` when choosing skills; the body loads after.
- `evals/gate/climb/eval.py`, `split.py`, `search.json`, `holdout.json`: the evaluator and its data.
- `evals/agent-optimization-2026-10-17/harness.py`: `run()`, `install()`, `verdict()`, scaffolds, the tool denylist for trigger cases (no Bash, no Write).
- Budget: about $0.20 per search eval, $0.12 per holdout; keep the run under $15 and about 40 tries.

## Known so far

- Today's descriptions are long single sentences packed with nouns. Haiku passes negatives reliably (9/9) and misses positives about half the time, so the failure is under-triggering, not over-triggering.
- Failing positives in the 2026-10-23 seed run (full set): `t-entry`, `t-glob`, `t-onboard`, `t-agentready`, `t-guard`, `t-scriptsync`, `t-add-signal`, `t-compare`, `t-upgrade` (loaded roblox-vide instead), `t-pin-mismatch`, `t-fix-skill` (roblox-vide), `first-time-selene-config`, `profilestore-wally-toml`, `rokit-stylua`, `vide-skill-missing` (roblox-vide). Several misses went to a library skill (`roblox-vide`) when the task mentioned a library: the acquisition skill's description does not outrank the library's for "the skill is missing or wrong" prompts.
