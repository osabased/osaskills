# Review and save project guidance

Use when requested guidance, assessment, or a correction is to be saved. Read [project guidance](project-profile.md). Preserve the recorded preference to review these writes, including revisions; code implementation can continue independently.

## Review the concrete result

Show the content or precise diff, affected project/destination, create/append/update operation, and any instruction pointer with its entry-directory visibility. Keep factual guidance, optional assessment, and material gaps identifiable.

Do not write the project guide, assessment, or instruction pointer before the user approves the preview. A requested scratch/review artifact may be prepared without activating project instructions. Approval already covering the exact operation or a setup preview needs no new confirmation. Routine factual adjustments covered by that approval can proceed; changed scope, topology, ownership, or recommendations need a revised preview. Honor explicit exact-edit review requirements.

Documentation approval does not authorize unselected modernization, installs, or architecture changes. If saving is declined or pending, use available session context for separately authorized work.

## Save and verify

1. Recheck the destination and preserve concurrent/user content. Reconcile overlapping edits before applying the approved change. Prefer the existing guide; use `.agents/roblox/project.md` only when no equivalent exists. Preserve legacy scoped rules.
2. Add or update only the approved small instruction pointer. Reuse an existing pointer convention rather than creating another authority. For a managed block, adapt this path to the actual instruction file:

```markdown
<!-- structure-roblox-projects:onboarding:start -->
## Roblox project guidance

Before Roblox work in this project, read `.agents/roblox/project.md`. Check relevant claims against their linked sources. Present guide corrections for review before saving.
<!-- structure-roblox-projects:onboarding:end -->
```

3. Replace only an existing managed block or append the approved pointer, preserving other bytes except necessary newlines. Ancestor pointers are separate reviewed writes. Check link resolution, project scope, and actual instruction discovery. If unavailable, report the visibility limitation and required entry point.
4. Inspect the diff against the approved operation and the implemented project. Report saved content and remaining evidence gaps. An approved setup may include guidance saving; material implementation changes require a revised preview before saving inaccurate guidance.

Persistence is complete when the approved guide/pointer is saved without unrelated changes, links resolve, and reachability is established or accurately limited. Recommendations remain proposals and unrun Studio/host checks remain unverified.
