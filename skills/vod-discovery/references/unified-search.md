# Unified local evidence search

Use `scripts/unified_search.py` to investigate a question across prepared speech, optional existing semantic passages, and optional Windows OCR reports in one operation. It adds no dependencies for keyword/OCR retrieval: Python's SQLite must include [FTS5](https://www.sqlite.org/fts5.html). Semantic retrieval uses the existing pinned local model and environment described in [speech-search.md](speech-search.md); this command never downloads a model or invokes an external inference service.

Preparation and literal indexing remain unchanged. Build `vod.py index` first, passing one prepared folder per source. Unified indexing reads the current aggregate transcripts and exact raw occurrence references without altering evidence, review ledgers, events, queues, or export files. `vod.py search` keeps its original literal-search behavior.

## Build a snapshot

Speech only:

```powershell
work/vod-env/Scripts/python.exe <skill>/scripts/unified_search.py index --literal-index work/speech-index --out work/unified-index
```

Add an existing semantic index and OCR report:

```powershell
work/vod-env/Scripts/python.exe <skill>/scripts/unified_search.py index --literal-index work/speech-index --semantic-index work/semantic-index --ocr-report work/ocr-results.json --detail-folder work/alice-detail-01 --out work/unified-index
```

`--ocr-report` and `--detail-folder` can be repeated. OCR reports must use the existing `vod-frame-ocr/v1` format generated by [ocr_frames.ps1](../scripts/ocr_frames.ps1). Reports retain raw recognized text, image hashes, source-local timestamps, and input-manifest hashes. OCR does not run automatically over every frame. Coverage reports exactly which reports and frames were processed, including frames with no recognized text; unprocessed footage remains unsearched by OCR.

Every OCR image/path/timestamp must match a prepared `frames.json`, or the `frames.json` of an explicit `--detail-folder`. Detail folders bind their `packet.json` source path to the indexed source path; their exact recorded timestamps remain authoritative. An arbitrary list of images or an OCR report alone cannot establish source clocks. Crops require a documented frame-map workflow before they can be indexed. Different source files are not interchangeable even if their content looks similar.

If an older OCR report uses short source aliases, supply `--source-map work/ocr-source-map.json`. Its explicit mapping must name the current source ID and the exact indexed media path:

```json
{
  "schema": "vod-ocr-source-map/v1",
  "sources": [
    {"ocr_source_id": "alice", "source_id": "actual-source-id", "source": "D:/project/alice.mp4"}
  ]
}
```

This binds an alias only. It never changes recognized text or transfers clocks between different media. Results preserve the original OCR source alias in their report references.

An optional semantic index must reference this exact current literal index. Models are not loaded during unified indexing. Identical evidence reuses the existing database. Rebuild after adding completed packets, changing transcripts, refreshing OCR, or changing an optional index. Existing immutable build folders are preserved; a successful build atomically publishes `unified.json`. Interrupted or failed builds do not replace a published snapshot.

## Investigate one question or a batch

```powershell
work/vod-env/Scripts/python.exe <skill>/scripts/unified_search.py search --index work/unified-index --query 'Josh offers a truce' --limit 20 --out work/truce-search.json
```

For an index that includes semantic retrieval, use its existing local environment and model:

```powershell
work/semantic-env/Scripts/python.exe <skill>/scripts/unified_search.py search --index work/unified-index --model-dir work/models/bge-small-en-v1.5 --query 'Josh offers a truce' --out work/truce-search.json
work/semantic-env/Scripts/python.exe <skill>/scripts/unified_search.py search-many --index work/unified-index --model-dir work/models/bge-small-en-v1.5 --queries work/questions.json --out work/search-results.json
```

`questions.json` is a nonempty JSON array of query strings. `search-many` keeps one semantic model loaded across queries while revalidating evidence and artifacts for each query. The Python `SearchSession` API does the same. An output file must be fresh; existing search results are preserved.

Default search includes every indexed channel. The result states `not_indexed` for absent OCR or semantic evidence. If a requested channel is unavailable, stale, or fails, the operation fails explicitly. An index containing semantic retrieval requires `--model-dir`; to investigate only its lexical evidence, select channels explicitly, for example `--channels exact speech ocr`. Available channel names are `exact`, `speech`, `ocr`, and `semantic`. No channel failure is silently presented as a complete search.

## Ranking and evidence references

- `exact`: case-insensitive, Unicode-casefolded literal substring matches, including punctuation. Footage text and queries are never executed as SQL or FTS query syntax.
- `speech`: FTS5 keyword matches over speech, ranked with BM25. Query words use OR, so a longer investigative question can find partial lexical matches.
- `ocr`: the same keyword method over visible text, with raw spelling preserved. Try variants for misrecognized names; do not silently correct transcripts or OCR.
- `semantic`: the existing local meaning-based speech model. Retrieved segment/context passages expand to their exact current raw speech occurrences. This model does not embed OCR or images.

Lists combine using reciprocal rank fusion: each channel contributes `1 / (60 + rank)`. Results expose the contributing channel ranks and original BM25 or semantic similarity scores. Raw BM25 and cosine similarity are not added together. Scores are retrieval priorities, not confidence or event importance. A semantic context passage can contribute several exact speech segments at its passage rank; inspect the quoted context rather than interpreting each expansion as an independent model judgment.

Speech hits identify source path/ID, audio stream, exact source-local start/end, text, and all matching raw transcript file/segment occurrences with hashes. Raw transcript text, including original whitespace, stays in the occurrence reference. Only exactly identical source/stream/start/end/text evidence combines provenance from overlapping preparation packets. Repeated lines, different sources, and different audio streams remain distinct. Speech and visible text at the same instant remain separate evidence.

Visible-text hits identify one sampled source timestamp, image path/hash, the authoritative frame-map reference, and every contributing OCR report/frame index. A sampled image has no invented duration. Validate OCR wording against the image before writing a factual marker or associating POVs.

`--limit` bounds returned evidence to 1–200 results. `--candidate-limit` bounds each lexical candidate list and semantic passage list to 1–200, default 100, and must be at least `--limit`. Semantic passages can expand to several exact evidence segments. The result exposes per-channel counts, candidate limits, `at_limit`, and `more_available`; truncation means narrow the question or raise the limit and continue investigating. `at_limit` alone does not establish that more matches exist. No ranking threshold discards footage or changes the discovery coverage ledger.

Every query verifies prepared-input signatures, aggregate/raw-evidence hashes, OCR report/input-manifest/image hashes, mapping files, and the generated database. Semantic search also validates its existing model and index. A concurrent snapshot replacement or changed evidence during a query rejects that result. Restore changed evidence or rebuild the affected indexes before continuing.

Search is a discovery aid. Even irrelevant questions can retrieve nearby semantic passages; no match does not establish absence. Continue visual review and preserve quiet or uncertain candidates. Similar text or frames never proves synchronized POVs. Use [the benchmark](benchmark.md) with independently reviewed annotations to measure useful moments found and investigation time; software fixtures do not establish discovery quality.
