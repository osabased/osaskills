# Changing a decision protocol

Use when revising this skill, another decision process, or a caller that depends on it.

1. Name the target behavior and apply direction selection to that change once. Prefer the smallest coherent intervention that could improve observed behavior.
2. Check affected triggers, routes, references, output contracts, and caller boundaries. Every route must reach an owner, valid outcome, and stopping condition. Evidence investigations return to their requesting comparison step or the standalone applicability router; they never become a parallel decision owner.
3. Validate the affected behavior with relevant [evaluation cases](../evals/README.md) and task-specific scenarios. Keep answer expectations out of evaluated agents' context. Distinguish static checks and walkthroughs from observed agent runs; neither establishes measured improvement.
4. Run one adversarial pass after the first verified revision. Correct concrete failures and rerun affected checks.

Stop when required checks pass and no demonstrated material defect remains. Additional passes require a failed check, contradiction, material new evidence, or explicit user requirement. Reapplying the protocol or verifying verification supplies no new evidence; stylistic preference alone does not reopen a settled change.
